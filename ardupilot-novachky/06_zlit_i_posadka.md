# Урок 6. Зліт і посадка

## Що вивчимо

- Плагін `Action`: `arm()`, `takeoff()`, `land()`.
- Як перевіряти, чи команда виконалась (`Action::Result`).
- Чому треба **чекати** (висоти, посадки) і як це робити циклом `while`.

## План програми

Це той самий план, що ти робив мишкою в уроці 3:

```
1. Дочекатися GPS
2. ARM
3. TAKEOFF на 10 м
4. Чекати, поки висота стане ~10 м
5. Висіти 5 секунд
6. LAND
7. Чекати, поки мотори вимкнуться (DISARM)
```

## Запуск

SITL і Mission Planner працюють. **Ubuntu:**

```bash
./scripts/run.sh lesson06_takeoff_land 2>/dev/null
```

Дивись у Mission Planner: дрон злітає і сідає.

**Що маєш побачити:**

```

  набираємо висоту: -0.005 м
  набираємо висоту: 1.546 м
  набираємо висоту: 8.565 м

  сідаємо: 9.999 м
```

Рядки «зліт поки не вдається» з'являються, якщо запустити програму одразу після старту SITL —
автопілот ще «прогрівається». Якщо SITL працює вже хвилину — їх не буде.

## Розбір коду

### Плагін Action

```cpp
#include <mavsdk/plugins/action/action.hpp>
...
Action action{system.value()};
```

### Кожна команда повертає результат

```cpp
Action::Result result = action.land();
std::cout << "LAND: " << result << "\n";       // надрукує Success, Failed, Denied...
if (result != Action::Result::Success) { ... }  // команда не виконалась
```

**Завжди перевіряй результат.** `Success` означає «автопілот прийняв команду» — **не** «дрон уже сів»!
Тому далі ми чекаємо.

### Функція `arm_and_takeoff`

ARM, зліт і очікування висоти зібрані в одну функцію, бо вони знадобляться в кожному наступному уроці.

```cpp
bool arm_and_takeoff(Action& action, Telemetry& telemetry, float altitude_m)
```

- `Action& action` — передаємо **посилання** на об'єкт (не копію), щоб функція керувала тим самим дроном.
- повертає `true`, якщо злетіли, і `false`, якщо ні.

Усередині — спроби в циклі:

```cpp
for (int attempt = 1; attempt <= 20; attempt++) {
    if (action.arm() == Success) {
        if (action.takeoff() == Success) {
            started = true;
            break;                // вийти з циклу — злетіли
        }
    }
    wait_seconds(3);              // не вийшло — почекати і спробувати ще
}
```

Чому так? Перші ~30 секунд після старту SITL автопілот ще не знає точно, де він (вкладка Messages:
`Mode change to Guided failed: requires position`). ARM уже може пройти, а зліт — ні.
На справжньому дроні так само: поки GPS не «зловив» супутники, летіти не можна.

### Чекати, поки щось станеться

```cpp
while (telemetry.position().relative_altitude_m < altitude_m - 0.5f) {
    if (!telemetry.armed()) {        // мотори раптом вимкнулись?
        return false;                // тоді чекати немає сенсу
    }
    wait_seconds(1);
}
```

Поки висота менша за потрібну (з допуском 0.5 м) — чекаємо секунду і перевіряємо знову.
Перевірка `armed()` всередині — **захист від вічного циклу**: якщо дрон не злетить, програма не зависне.

### Посадка

```cpp
action.land();
while (telemetry.armed()) {   // поки мотори увімкнені
    wait_seconds(1);
}
```

Після посадки ArduPilot сам робить DISARM. Ми чекаємо саме цього.

## Типові помилки

| Помилка | Що буде |
|---|---|
| не чекати висоти після `takeoff()` | наступна команда прийде, коли дрон ще на землі |
| `while (висота < 10)` без допуску `- 0.5f` | дрон висить на 9.9 м — цикл нескінченний |
| немає перевірки `armed()` у циклі очікування | якщо зліт не вдався — програма висить вічно |
| не перевіряти `Action::Result` | не зрозуміло, чому дрон нічого не робить |

## Вправи

1. Зміни висоту зльоту на 25 м (`TAKEOFF_ALTITUDE_M`).
2. Висіти не 5, а 15 секунд, і щосекунди друкувати висоту.
3. Заміни `land()` на `return_to_launch()` (RTL). Чи відрізняється поведінка тут? Чому? (Підказка: де зараз дрон відносно дому?)
4. Додай друк заряду батареї до зльоту і після посадки. Скільки «з'їв» політ?
5. (★) Під час «висіння» натисни в Mission Planner **Arm/Disarm**, щоб вимкнути мотори.
   Що зробить програма? Як зробити, щоб вона це помітила і надрукувала попередження?

## Коротко

- `Action`: `arm()`, `takeoff()`, `land()`, `return_to_launch()`.
- `Success` = «команду прийнято», а не «виконано». Результат треба **чекати** циклом `while`.
- У кожному циклі очікування — запобіжник від вічного зависання.
