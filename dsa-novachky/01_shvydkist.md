# Урок 1. Як виміряти швидкість алгоритму

## Що вивчимо

- Чому «скільки секунд працює програма» — погана міра.
- Як рахувати **кроки** алгоритму.
- Що означають O(1), O(n), O(n²), O(log n) — без страшної математики.

## Проблема: секунди брешуть

Одна й та сама програма на ноутбуці працює 1 секунду, а на польотному контролері дрона — 50 секунд.
Тому програмісти порівнюють алгоритми не в секундах, а питанням:

> **Як зростає кількість кроків, коли даних стає більше?**

## Чотири типові випадки

Уяви, що в тебе є список з n точок маршруту.

### O(1) — «константа»: кроків завжди однаково

Взяти **першу** точку маршруту — 1 крок. Неважливо, 10 точок чи мільйон.

```cpp
int first = values[0];   // 1 крок
```

### O(n) — «лінійно»: один прохід по всіх

Порахувати **суму** — треба подивитися на кожен елемент один раз. 10 точок — 10 кроків,
1000 точок — 1000 кроків.

```cpp
for (int i = 0; i < n; i++) {
    sum = sum + values[i];   // виконається n разів
}
```

### O(n²) — «квадратично»: кожен з кожним

Перевірити, чи не летять **якісь два дрони** надто близько: порівняти кожен з кожним.
Цикл у циклі:

```cpp
for (int i = 0; i < n; i++) {
    for (int j = i + 1; j < n; j++) {
        // порівняти дрон i з дроном j
    }
}
```

10 дронів — 45 пар. 1000 дронів — майже **півмільйона** пар.

### O(log n) — «логарифм»: щоразу ділимо навпіл

Скільки разів можна поділити 1000 навпіл, поки не залишиться 1? Лише 9–10 разів.
Мільйон — 20 разів. Так працює бінарний пошук (урок 4) — неймовірно швидко.

## Запусти приклад

```bash
cd code/lesson01
g++ -std=c++17 -Wall example.cpp -o example
./example
```

Програма рахує кроки для різних n:

```
     n | перший | сума (n) | пари (n*n/2) | ділення навпіл
-------+--------+----------+--------------+---------------
    10 |      1 |       10 |           45 |      3
   100 |      1 |      100 |         4950 |      6
  1000 |      1 |     1000 |       499500 |      9
 10000 |      1 |    10000 |     49995000 |     13
```

Подивись, що відбувається, коли n росте в 10 разів (10 → 100 → 1000):

| Алгоритм | Кроків стало | Назва |
|---|---|---|
| перший елемент | стільки ж | O(1) |
| сума | у 10 разів більше | O(n) |
| пари | у **100** разів більше | O(n²) |
| ділення навпіл | лише на 3 більше | O(log n) |

## Як це читати: «O велике»

Запис **O(n)** читається «О від ен». Він означає: «кількість кроків росте приблизно як n».
Дрібниці відкидаємо: n/2 кроків, 2n кроків, n + 5 кроків — усе це O(n).
Нас цікавить лише **як швидко росте**.

| Запис | Як читати | Від найшвидшого до найповільнішого |
|---|---|---|
| O(1) | константа | найшвидше |
| O(log n) | логарифм | дуже швидко |
| O(n) | лінійно | нормально |
| O(n²) | квадратично | повільно на великих даних |

## Типові помилки

- **Думати, що цикл у циклі — завжди O(n²).** Якщо внутрішній цикл завжди робить 3 кроки —
  це O(3·n) = O(n). Дивись, *скільки разів* виконується внутрішній цикл.
- **Порівнювати на маленьких даних.** На 10 елементах усе працює миттєво. Різниця видна на тисячах.

## Перевір себе

1. Функція шукає найбільше число в масиві з 1000 елементів. Скільки приблизно кроків? Яке це O?
<details><summary>Відповідь</summary>Приблизно 1000 кроків — треба подивитися на кожен елемент. O(n).</details>

2. Алгоритм O(n²) обробляє 100 точок за 1 мілісекунду. Скільки часу на 1000 точок?
<details><summary>Відповідь</summary>Точок у 10 разів більше → кроків у 10² = 100 разів більше → 100 мс.</details>

3. Що швидше на мільйоні елементів: O(n) чи O(log n)? У скільки разів приблизно?
<details><summary>Відповідь</summary>O(log n): ~20 кроків проти 1 000 000. Приблизно в 50 000 разів.</details>

## Коротко

- Швидкість алгоритму міряємо **кроками**, а не секундами.
- O(1) — завжди однаково, O(n) — один прохід, O(n²) — кожен з кожним, O(log n) — ділимо навпіл.
- На великих даних різниця між O(n) і O(n²) — це різниця між «миттєво» і «зависло».
