# Урок №160. Композиція і правила проєктування

## 1. Що таке композиція

**Композиція (composition)** — це побудова складного класу з інших класів, коли один об'єкт **містить** інший.

Це відношення **«HAS-A»** (має):

```
Inheritance:   Dog IS-A Animal        (собака Є твариною)
Composition:   Car HAS-A Engine       (автомобіль МАЄ двигун)
```

Різниця між відношеннями:

| Відношення | Означає | Приклад |
| ---------- | ------- | ------- |
| IS-A (наслідування) | клас є різновидом | `Dog : Animal` |
| HAS-A (композиція)  | клас містить інший | `Car` має поле `Engine` |

## 2. Простий приклад композиції

```c++
#include <iostream>
using namespace std;

class Engine {
public:
    void start() {
        cout << "Engine started\n";
    }
};

class Car {
private:
    Engine engine;   // Car «має» Engine (композиція)

public:
    void start() {
        engine.start();   // делегуємо роботу двигуну
    }
};

int main() {
    Car car;
    car.start();
    return 0;
}
```

**Розбір**:
- У `Car` є поле `engine` типу `Engine`. Об'єкт `Car` буквально містить у собі об'єкт `Engine`.
- Метод `Car::start()` **делегує** виконання двигуну — викликає `engine.start()`.
- Клас `Car` не «спадкоємець» двигуна. Він ним **користується**.

Результат:
```
Engine started
```

## 3. Навіщо композиція, якщо є наслідування?

### Проблема з наслідуванням у складних випадках

Іноді наслідування «підтягує» все від батька, навіть те, що не потрібно:

```c++
class Bird {
public:
    void fly() {}
};

class Penguin : public Bird {
    // проблема: пінгвін не літає, але «успадкував» fly()
};
```

За допомогою композиції «здібності» можна додавати точково:

```c++
class Flyable {
public:
    void fly() { cout << "Flying\n"; }
};

class Penguin {
private:
    Flyable ability;   // або без нього — пінгвін просто не вміє літати
};

class Sparrow {
private:
    Flyable ability;   // спарроу вміє літати
public:
    void fly() { ability.fly(); }
};
```

### Коли наслідування, коли композиція?

| Ситуація | Підхід |
| -------- | ------ |
| «A є різновидом B» (IS-A) | Наслідування |
| «A користується B» (HAS-A) | Композиція |
| Хочете повністю контролювати доступ до членів | Композиція |
| Потрібне повторне використання коду | Композиція — безпечніша |

**Правило**: намагайтесь спочатку думати про композицію. Якщо відношення дійсно «IS-A» — тоді наслідування.

## 4. Композиція + конструктори

### Проблема: поле-об'єкт без конструктора за замовчуванням

```c++
class Engine {
public:
    Engine(string type) {   // немає конструктора без параметрів
        cout << "Engine created: " << type << "\n";
    }
};

class Car {
private:
    Engine engine;

public:
    Car(string type)
        : engine(type)   // ✅ ініціалізуємо Engine через список ініціалізації
    {}
};
```

**Чому обов'язково через список ініціалізації?**
- Поле `engine` створюється **до** тіла конструктора `Car`.
- Якщо `Engine` не має конструктора за замовчуванням, потрібно надати аргументи — i не можна зробити це в тілі конструктора.

**Помилка**:
```c++
Car(string type) {
    // ❌ engine вже створений! Тут можна лише присвоїти, але Engine(Type)
    //    не можна викликати після створення об'єкта.
}
```

### Порядок створення при композиції

```c++
int main() {
    Car car("V8");
    return 0;
}
```

Результат:
```
Engine created: V8
```

1. Спочатку створюється поле `engine` (Engine).
2. Потім викликається тіло конструктора `Car`.

### Приклад з двома об'єктами-членами

```c++
#include <iostream>
using namespace std;

class Engine {
public:
    Engine(string type) {
        cout << "Engine: " << type << "\n";
    }
};

class Wheel {
public:
    Wheel(int count) {
        cout << "Wheels: " << count << "\n";
    }
};

class Car {
private:
    Engine engine;
    Wheel  wheel;

public:
    Car(string type, int wheels)
        : engine(type), wheel(wheels)
    {
        cout << "Car created\n";
    }
};

int main() {
    Car car("V8", 4);
    return 0;
}
```

Результат:
```
Engine: V8
Wheels: 4
Car created
```

**Порядок**: спочатку члени (`engine`, `wheel`), потім тіло конструктора `Car`.

## 5. Коли використовувати (правила проєктування)

Короткі правила гарного дизайну:

1. **Поля зазвичай `private`** — приховуйте деталі реалізації.
2. **Використовуйте конструктори** для коректного початкового стану.
3. **Використовуйте список ініціалізації** замість присвоєння в тілі.
4. **Використовуйте `override`** при перевизначенні віртуальних методів.
5. **Базовий клас із поліморфізмом повинен мати `virtual` деструктор**.
6. **Не використовуйте наслідування просто для повторного використання коду** — якщо це лише код, краще композиція.
7. **Якщо відношення «HAS-A»** — розгляньте композицію.
8. **Якщо відношення «IS-A»** — наслідування може бути доречним.

## 6. Типові помилки

**Помилка 1: поле без конструктора за замовчуванням і не через список ініціалізації**
```c++
class Engine { public: Engine(string) {} };
class Car {
    Engine engine;
public:
    Car() {}   // ❌ помилка — Engine(Type) не викликаний
};
```

**Помилка 2: наслідування замість композиції**
```c++
class Car : public Engine {   // ❌ Car НЕ є Engine!
    // це помилка логіки — машина не є двигуном
};
```
Правильно:
```c++
class Car {
    Engine engine;   // ✅ Car має Engine
};
```
