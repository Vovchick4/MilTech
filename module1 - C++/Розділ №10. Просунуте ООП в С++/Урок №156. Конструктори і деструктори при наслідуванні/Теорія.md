# Урок №156. Конструктори і деструктори при наслідуванні

## 1. Порядок виклику конструкторів

Це одна з найважливіших тем у ООП. Неправильне розуміння порядку конструкторів призводить до багатьох помилок.

**Правило просте**:

```
Спочатку створюється базовий (батьківський) клас,
  потім — дочірній.
```

Тобто: **Base → Derived**.

Аналогія: щоб побудувати другий поверх, потрібно спочатку звести перший. Базовий клас — це «перший поверх».

## 2. Порядок виклику деструкторів

**Навпаки**: спочатку знищується дочірній, потім базовий.

```
Derived destructor
        ↓
Base destructor
```

Аналогія: демонтують верхні поверхи будівлі першими.

## 3. Детальний приклад

```c++
#include <iostream>
using namespace std;

class Animal {
public:
    Animal(string name) {
        cout << "Animal constructor: " << name << "\n";
    }

    ~Animal() {
        cout << "Animal destructor\n";
    }
};

class Dog : public Animal {
public:
    Dog(string name)
        : Animal(name)   // явно викликаємо конструктор базового класу
    {
        cout << "Dog constructor: " << name << "\n";
    }

    ~Dog() {
        cout << "Dog destructor\n";
    }
};

int main() {
    cout << "--- Створення об'єкта ---\n";
    Dog dog("Rex");

    cout << "\n--- Знищення об'єкта ---\n";
    return 0;
}
```

**Результат**:

```
--- Створення об'єкта ---
Animal constructor: Rex
Dog constructor: Rex

--- Знищення об'єкта ---
Dog destructor
Animal destructor
```

## 4. Розбір: що відбувається і чому

### При створенні:

```c++
Dog dog("Rex");
```

Коли компілятор бачить створення `Dog`, він:
1. **Спочатку** викликає `Animal(name)` — бо `Dog` залежить від `Animal` і не може існувати без нього.
2. **Потім** викликає тіло конструктора `Dog` (всередині фігуристих дужок).

Тому першим буде виведено `Animal constructor: Rex`, а потім `Dog constructor: Rex`.

### При знищенні:

Потім ми повертаємо 0 з `main()`, і об'єкт `dog` знищується. Порядок **зворотний**:
1. **Спочатку** викликається `~Dog()`.
2. **Потім** викликається `~Animal()`.

Це гарантує, що дочірній клас «бачить» ще цілий базовий клас під час свого знищення.

### Чому саме такий порядок?

- **Конструктори: Base → Derived** — спочатку базовий, бо дочірній може використовувати поля/методи базового. Базовий повинен бути готовий першим.
- **Деструктори: Derived → Base** — навпаки, бо під час знищення базового класу не можна звертатись до полів, які вже знищені.

## 5. Шість випадків конструкторів при наслідуванні

---

### Випадок 1: Батьківський клас має конструктор за замовчуванням

```c++
class Animal {
public:
    Animal() {
        cout << "Animal default constructor\n";
    }
};

class Dog : public Animal {
public:
    Dog() {
        cout << "Dog default constructor\n";
    }
};
```

```c++
Dog dog;   // ✅ працює
```

Результат:
```
Animal default constructor
Dog default constructor
```

**Що відбувається**: `Dog` не викликає явно `Animal()` у списку ініціалізації, але компілятор **неявно** викликає `Animal()` перед `Dog()`. Це тому, що `Animal` має конструктор без параметрів — компілятор може викликати його автоматично.

---

### Випадок 2: Батьківський клас має ТІЛЬКИ конструктор з параметрами

```c++
class Animal {
public:
    Animal(string name) {
        cout << "Animal constructor: " << name << "\n";
    }
};
```

Тепер `Animal` **не** має конструктора без параметрів. Що станеться, якщо `Dog` не викличе його явно?

```c++
class Dog : public Animal {
public:
    Dog() {
        cout << "Dog constructor\n";
    }
};
```

```c++
Dog dog;   // ❌ ПОМИЛКА компіляції!
```

**Чому**: компілятор намагається неявно викликати `Animal()`, але його не існує. Тому це помилка.

**Розв'язок**: потрібно **явно** викликати `Animal(string)` через список ініціалізації:

```c++
class Dog : public Animal {
public:
    Dog(string name)
        : Animal(name)   // ✅ явно передаємо параметр батьківському конструктору
    {
        cout << "Dog constructor: " << name << "\n";
    }
};
```

```c++
Dog dog("Rex");   // ✅ працює
```

Результат:
```
Animal constructor: Rex
Dog constructor: Rex
```

**Головне правило**: якщо батьківський клас не має конструктора за замовчуванням, дочірній **зобов'язаний** явно викликати один з конструкторів батька через список ініціалізації.

---

### Випадок 3: Передача кількох параметрів

```c++
class Animal {
public:
    Animal(string name, int age) {
        cout << "Animal: " << name << ", " << age << " years\n";
    }
};

class Dog : public Animal {
public:
    Dog(string name, int age)
        : Animal(name, age)   // передаємо обидва параметри
    {
        cout << "Dog constructor\n";
    }
};
```

```c++
Dog dog("Rex", 5);
```

Результат:
```
Animal: Rex, 5 years
Dog constructor
```

**Розбір**: параметри `name` і `age` передаються «транзитом» від конструктора `Dog` до конструктора `Animal`. `Dog` не обов'язково використовувати ці параметри самостійно — він може просто перенаправити їх базовому класу.

---

### Випадок 4: Ініціалізація власних полів дочірнього класу

```c++
class Animal {
protected:
    string name;
    int age;

public:
    Animal(string name, int age)
        : name(name), age(age)   // ініціалізація полів Animal
    {
        cout << "Animal constructor\n";
    }

    void info() {
        cout << name << ", " << age << " years\n";
    }
};

class Dog : public Animal {
private:
    string breed;

public:
    Dog(string name, int age, string breed)
        : Animal(name, age),    // ініціалізація базового класу
          breed(breed)          // ініціалізація власного поля
    {
        cout << "Dog constructor\n";
    }

    void print() {
        info();   // викликаємо метод батьківського класу
        cout << "Порода: " << breed << "\n";
    }
};
```

```c++
Dog dog("Rex", 3, "Labrador");
dog.print();
```

Результат:
```
Animal constructor
Dog constructor
Rex, 3 years
Порода: Labrador
```

**Розбір**:
- `: Animal(name, age)` — ініціалізація полів `name` і `age` базового класу.
- `, breed(breed)` — ініціалізація власного поля `breed` класу `Dog`.
- Порядок у списку ініціалізації визначається **порядком оголошення полів** у класі, а НЕ порядком у списку ініціалізації. Але практика рекомендує писати їх у тому ж порядку, що й оголошення.
- Конструктор базового класу викликається **завжди першим**, незалежно від позиції в списку ініціалізації.

### Випадок 5: Кілька рівнів наслідування

```
    Animal
       ↓
    Mammal
       ↓
      Dog
```

```c++
#include <iostream>
using namespace std;

class Animal {
public:
    Animal(string name) {
        cout << "1. Animal constructor: " << name << "\n";
    }

    ~Animal() {
        cout << "4. Animal destructor\n";
    }
};

class Mammal : public Animal {
public:
    Mammal(string name)
        : Animal(name)
    {
        cout << "2. Mammal constructor\n";
    }

    ~Mammal() {
        cout << "3. Mammal destructor\n";
    }
};

class Dog : public Mammal {
public:
    Dog(string name)
        : Mammal(name)
    {
        cout << "3. Dog constructor\n";
    }

    ~Dog() {
        cout << "2. Dog destructor\n";
    }
};
```

```c++
int main() {
    Dog dog("Rex");
    cout << "--- Програма працює ---\n";
    return 0;
}
```

Результат:
```
1. Animal constructor: Rex
2. Mammal constructor
3. Dog constructor
--- Програма працює ---
2. Dog destructor
3. Mammal destructor
4. Animal destructor
```

**Порядок**:
- Конструктори: **Animal → Mammal → Dog** (від «найстарішого» до «наймолодшого»).
- Деструктори: **Dog → Mammal → Animal** (навпаки).

Кожен нащадок гарантує, що при його створенні «нижчі» класи вже створені, а при знищенні — ще працюють.

---

### Випадок 6: Деструктори при наслідуванні — детально

Порядок знищення — **завжди зворотний** до створення:

```
Створення:   Base → Derived
Знищення:   Derived → Base
```

Для ланцюжка `A → B → C → D`:

| Етап        | Порядок      |
| ----------- | ------------ |
| Конструктор | A → B → C → D |
| Деструктор  | D → C → B → A |

Це гарантує безпеку: кожен деструктор «бачить» ще цілий об'єкт «нижче» себе.

**Важливо**: саме тому при використанні поліморфізму через базовий клас базовий деструктор повинен бути **`virtual`** (детально — в уроці про віртуальні деструктори).

## 6. Основна помилка: забули викликати базовий конструктор

```c++
class Animal {
public:
    Animal(string name) {}   // немає конструктора за замовчуванням
};

class Dog : public Animal {
public:
    Dog() {}   // ❌ ПОМИЛКА: компілятор не може викликати Animal()
};
```

**Що тут не так**: `Dog()` не викликає жодний конструктор `Animal`, а `Animal()` без параметрів не існує.

**Розв'язки**:

а) Додати конструктор за замовчуванням у `Animal`:
```c++
class Animal {
public:
    Animal() {}
    Animal(string name) {}
};
```

б) Або (краще) явно викликати `Animal(string)`:
```c++
class Dog : public Animal {
public:
    Dog()
        : Animal("Unknown")   // ✅ явно передаємо значення за замовчуванням
    {}
};
```

## 7. Коли використовувати

- **Завжди** явно викликайте базовий конструктор у списку ініціалізації, якщо він приймає параметри.
- Якщо базовий конструктор не приймає параметрів — можна покластись на неявний виклик.
- Для багаторівневого наслідування пам'ятайте: кожен клас викликає конструктор свого «батька», а не «діда» напряму. Ланцюжок дотримується автоматично.

## 8. Типові помилки

**Помилка 1: Батьківський клас без default constructor, дочірній не викликає його**
```c++
class Animal { public: Animal(string) {} };
class Dog : public Animal { public: Dog() {} };  // ❌
```

**Помилка 2: Виклик конструктора батька не через список ініціалізації**
```c++
class Dog : public Animal {
public:
    Dog(string name) {
        Animal(name);   // ❌ це Створення тимчасового об'єкта, а не виклик конструктора!
    }
};
```
Правильно:
```c++
class Dog : public Animal {
public:
    Dog(string name)
        : Animal(name)   // ✅ це ініціалізація базового класу
    {}
};
```

## 9. Міні-завдання

Створіть ланцюжок наслідування: `Vehicle → Car → ElectricCar`.

- `Vehicle` має поле `brand` (string).
- `Car` має додаткове поле `doorsCount` (int).
- `ElectricCar` має додаткове поле `batteryCapacity` (int).

Кожен конструктор повинен виводити повідомлення про свій виклик, кожен деструктор — про своє знищення.
