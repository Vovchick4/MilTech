# Урок №159. Віртуальні деструктори, protected і getters/setters

## 1. Віртуальний деструктор

### Проблема: що станеться, якщо деструктор не віртуальний?

```c++
class Animal {
public:
    Animal() { cout << "Animal created\n"; }
    ~Animal() { cout << "Animal destroyed\n"; }   // НЕ virtual!
};

class Dog : public Animal {
public:
    Dog() { cout << "Dog created\n"; }
    ~Dog() { cout << "Dog destroyed\n"; }
};

int main() {
    Animal* animal = new Dog();
    delete animal;   // ❌ знищується ТІЛЬКИ частина Animal!
    return 0;
}
```

**Результат**:
```
Animal created
Dog created
Animal destroyed       // ⚠️ Dog destructor НЕ викликався!
```

**Що відбувається**: компілятор бачить тип вказівника (`Animal*`) і викликає `Animal::~Animal()`. Деструктор `Dog` НЕ викликається. Це **витечка пам'яті** (memory leak), якщо `Dog` виділяв ресурси.

### Розв'язання: virtual destructor

```c++
class Animal {
public:
    Animal() { cout << "Animal created\n"; }
    virtual ~Animal() { cout << "Animal destroyed\n"; }   // virtual!
};

class Dog : public Animal {
public:
    Dog() { cout << "Dog created\n"; }
    ~Dog() { cout << "Dog destroyed\n"; }
};

int main() {
    Animal* animal = new Dog();
    delete animal;
    return 0;
}
```

**Результат**:
```
Animal created
Dog created
Dog destroyed         // ✅ Dog деструктор викликався!
Animal destroyed
```

### Правило

**Якщо базовий клас має хоча б одну віртуальну функцію — деструктор обов'язково має бути `virtual`**.

### Навіщо це потрібно?

Під час поліморфізму ми часто маємо вказівник на базовий клас:

```c++
Animal* animal = new Dog(...);
delete animal;
```

Без `virtual` компілятор викликає `Animal::~Animal()`, бо він знає тип вказівника. З `virtual` компілятор «дивиться» на реальний тип об'єкта і викликає `Dog::~Dog()`.

### Наслідок для деструкторів при наслідуванні

З `virtual` деструктором порядок знищення залишається правильним:

```
delete animal;

Dog destructor         // 1. спочатку дочірній
Animal destructor      // 2. потім базовий
```

## 2. `protected` — детально

### Поведінка `protected`

Поле `protected` доступне:
- усередині самого класу;
- усередині **дочірніх** класів;
- **недоступне** з `main()` або інших зовнішніх функцій.

### Приклад: порівняння `private` і `protected`

```c++
class Animal {
private:
    string secretCode;

protected:
    string name;

public:
    Animal(string n, string code) : name(n), secretCode(code) {}
};

class Dog : public Animal {
public:
    Dog(string n, string code) : Animal(n, code) {}

    void show() {
        cout << name;          // ✅ protected — доступно нащадку
        // cout << secretCode; // ❌ private — НЕДОСТУПНО нащадку
    }
};

int main() {
    Dog dog("Rex", "12345");
    cout << dog.name;          // ❌ protected — недоступно з main()
    // cout << dog.secretCode; // ❌ private — недоступно з main()
    return 0;
}
```

### `protected` vs `private`: коли що використовувати?

| Ситуація | `private` | `protected` |
| -------- | --------- | ----------- |
| Поле потрібне тільки класу | ✅ | ❌ |
| Поле потрібне нащадкам | ❌ | ✅ |
| Бажаєте максимальний контроль | ✅ | ❌ |

**Порада**: надавайте перевагу `private`. Використовуйте `protected` лише коли нащадок **реально потребує** доступу до поля напряму.

## 3. `private` краще за `protected` — чому?

### Дизайн з `protected` (гірше)

```c++
class Animal {
protected:
    string name;

public:
    Animal(string n) : name(n) {}
};

class Dog : public Animal {
public:
    Dog(string n) : Animal(n) {}

    void showName() {
        cout << name;   // прямий доступ до поля
    }
};
```

### Дизайн з `private` (краще)

```c++
class Animal {
private:
    string name;

public:
    Animal(string n) : name(n) {}
    string getName() const { return name; }
};

class Dog : public Animal {
public:
    Dog(string n) : Animal(n) {}

    void showName() {
        cout << getName();   // через геттер
    }
};
```

### Переваги `private` + геттери

1. **Контроль**: геттер може здійснювати логіку (форматувати, фільтрувати).
2. **Гнучкість**: можна змінити внутрішню реалізацію класу, а публічний інтерфейс (геттери) не зміниться.
3. **Безпека**: жоден клас не може «обійти» логіку, напряму модифікувавши поле.

## 4. Getters і setters — практичні приклади

### Getters (отримання значення)

```c++
class Person {
private:
    string name;
    int age;

public:
    Person(string n, int a) : name(n), age(a) {}

    string getName() const { return name; }
    int getAge() const { return age; }
};
```

### Setters (встановлення значення з валідацією)

```c++
class Person {
private:
    string name;
    int age;

public:
    Person(string n, int a) : name(n) {
        setAge(a);   // використовуємо setter навіть у конструкторі
    }

    string getName() const { return name; }
    int getAge() const { return age; }

    void setAge(int a) {
        if (a >= 0 && a <= 150) {
            age = a;
        }
    }

    void setName(string n) {
        if (!n.empty()) {
            name = n;
        }
    }
};
```

### Getters/setters при наслідуванні

```c++
class Animal {
private:
    string name;

public:
    Animal(string n) : name(n) {}
    string getName() const { return name; }
};

class Dog : public Animal {
private:
    string breed;

public:
    Dog(string n, string b) : Animal(n), breed(b) {}

    string getBreed() const { return breed; }

    void show() {
        cout << "Ім'я: " << getName() << ", Порода: " << breed << "\n";
    }
};
```

Дочірній клас не може звертатись до `name` напряму (`private`), але може отримати його через геттер `getName()`.

## 5. Коли використовувати

- **`virtual` деструктор**: завжди, коли базовий клас використовується для поліморфізму.
- **`protected`**: коли нащадок дійсно потребує прямого доступу до поля.
- **`private` + геттери**: майже завжди — це кращий дизайн.
- **Setters**: коли потрібна валідація при зміні значення.

## 6. Типові помилки

**Помилка 1: базовий destructor не virtual**
```c++
class Base { public: ~Base() {} };   // ❌ без virtual
class Derived : public Base { public: ~Derived() {} };
Base* p = new Derived();
delete p;   // ❌ витікає пам'ять — Derived не знищується!
```

**Помилка 2: зловживання `protected`**
```c++
class Animal {
protected:
    string name;   // ⚠️ краще зробити private + getter
};
```
