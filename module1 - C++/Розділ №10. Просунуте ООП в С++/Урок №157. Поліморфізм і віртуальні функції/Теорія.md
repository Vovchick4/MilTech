# Урок №157. Поліморфізм і віртуальні функції

## 1. Поліморфізм: ідея максимально просто

**Поліморфізм** (від грецького «багато форм») — це можливість викликати **один і той самий метод** через базовий клас, але отримувати **різну поведінку** залежно від реального типу об'єкта.

Аналогія: уявіть кнопку «Увімкнути» на пульті. Для телевізора вона вмикає ТБ, для кондиціонера — вмикає кондиціонер, для музичної системи — вмикає музику. Кнопка одна, а дія залежить від того, на якому пристрої вона натиснута.

## 2. Спочатку: проблема без поліморфізму

```c++
class Dog {
public:
    void makeSound() { cout << "Woof!\n"; }
};

class Cat {
public:
    void makeSound() { cout << "Meow!\n"; }
};

int main() {
    Dog dog;
    Cat cat;

    dog.makeSound();   // Woof!
    cat.makeSound();   // Meow!

    // Але як обробити ВСІХ тварин одним циклом?
    // Dog* animals[] = { &dog, &cat };  // ❌ неможливо! різні типи!
}
```

Проблема: ми змушені викликати методи окремо для кожного типу. Якщо тварин стане 100 — код перетвориться на жах.

## 3. Розв'язання: один базовий клас + вказівники

```c++
#include <iostream>
using namespace std;

class Animal {
public:
    void makeSound() {
        cout << "Animal sound\n";
    }
};

class Dog : public Animal {
public:
    void makeSound() {
        cout << "Woof!\n";
    }
};

class Cat : public Animal {
public:
    void makeSound() {
        cout << "Meow!\n";
    }
};
```

### Спроба 1: без `virtual`

```c++
int main() {
    Dog dog;
    Cat cat;

    Animal* animals[] = { &dog, &cat };

    for (int i = 0; i < 2; i++) {
        animals[i]->makeSound();   // ❌ "Animal sound" для обох!
    }
    return 0;
}
```

**Що відбувається**: компілятор дивиться на тип **вказівника** (`Animal*`) і викликає `Animal::makeSound()`. Навіть хоча вказівники вказують на `Dog` і `Cat`, компілятор **не заглядає всередину** об'єкта — він дивиться на тип покажчика.

Це **статичний (ранній) зв'язування** (static binding) — метод вибирається на етапі компіляції.

### Спроба 2: з `virtual`

```c++
class Animal {
public:
    virtual void makeSound() {       // додаємо virtual
        cout << "Animal sound\n";
    }
};

class Dog : public Animal {
public:
    void makeSound() override {      // додаємо override
        cout << "Woof!\n";
    }
};

class Cat : public Animal {
public:
    void makeSound() override {
        cout << "Meow!\n";
    }
};

int main() {
    Dog dog;
    Cat cat;

    Animal* animals[] = { &dog, &cat };

    for (int i = 0; i < 2; i++) {
        animals[i]->makeSound();
    }
    return 0;
}
```

**Результат**:
```
Woof!
Meow!
```

**Що змінилось**: після додавання `virtual` компілятор **заглядає всередину** об'єкта під час виклику методу і викликає правильну версію — ту, що належить **реальному типу об'єкта** (Dog чи Cat).

Це **динамічний (пізній) зв'язування** (dynamic binding) — метод вибирається під час виконання програми.

## 5. `virtual` — окремий розбір

### Без `virtual`

```c++
class Animal {
public:
    void makeSound() { cout << "Animal sound\n"; }
};

class Dog : public Animal {
public:
    void makeSound() { cout << "Woof!\n"; }
};
```

```c++
Animal* animal = new Dog();
animal->makeSound();   // Animal sound  ( ❌ не те, що хотілось)
```

Компілятор викликає `Animal::makeSound()`, бо тип вказівника — `Animal*`.

### З `virtual`

```c++
class Animal {
public:
    virtual void makeSound() { cout << "Animal sound\n"; }
};

class Dog : public Animal {
public:
    void makeSound() override { cout << "Woof!\n"; }
};
```

```c++
Animal* animal = new Dog();
animal->makeSound();   // Woof!  ( ✅ правильна версія)
```

Тепер компілятор дивиться на об'єкт під вказівником і знаходить `Dog::makeSound()`.

### Ключове

| Атрибут | Без `virtual` | З `virtual` |
| ------- | ------------- | ----------- |
| Механізм | Статичний (compile-time) | Динамічний (run-time) |
| Вибір методу | За типом **вказівника** | За типом **об'єкта** |
| `Animal* p = new Dog(); p->method();` | `Animal::method()` | `Dog::method()` |

## 6. `override` — окремий розбір

Ключове слово `override` ставиться після назви методу в дочірньому класі:

```c++
class Dog : public Animal {
public:
    void makeSound() override { cout << "Woof!\n"; }
};
```

### Навіщо потрібен `override`?

1. **Захист від помилок**: якщо ви допустили помилку в назві методу, компілятор повідомить.

2. **Без `override` — мовчить**:
```c++
class Dog : public Animal {
public:
    void makesound() {   // ❌ неправильна назва (мала bути makeSound)
        cout << "Woof!\n";
    }
};
```
Ніякої помилки! Просто створиться новий метод `makesound()`, а `Animal::makeSound()` НЕ буде перевизначений. Поліморфізм не працюватиме.

3. **З `override` — компілятор знаходить помилку**:
```c++
class Dog : public Animal {
public:
    void makesound() override {   // ❌ ПОМИЛКА компіляції!
        cout << "Woof!\n";
    }
};
```
Компілятор каже: «Немає методу `makeSound()` у базовому класі, який можна перевизначити!».

### Правило

**Завжди** пишіть `override` для методів, які перевизначають віртуальні методи базового класу. Це безкоштовний захист від помилок.

## 7. Поліморфізм через посилання (не тільки вказівники)

```c++
void playSound(Animal& animal) {
    animal.makeSound();
}

int main() {
    Dog dog;
    Cat cat;

    playSound(dog);   // Woof!
    playSound(cat);   // Meow!
    return 0;
}
```

Поліморфізм працює і через посилання (`&`), не тільки через вказівники (`*`).

## 8. Повернення різних типів

```c++
Animal* createAnimal(const string& type) {
    if (type == "dog") return new Dog();
    if (type == "cat") return new Cat();
    return nullptr;
}

int main() {
    Animal* a = createAnimal("dog");
    a->makeSound();   // Woof!
    delete a;
    return 0;
}
```

Одна функція повертає різні типи об'єктів — і поліморфізм «знає», який метод викликати.

## 9. Коли використовувати

- Коли є спільний базовий клас і кілька нащадків із різною реалізацією одного методу;
- Коли потрібно обробляти різні об'єкти через єдиний інтерфейс (масив/вектор базових вказівників);
- Коли хочете «розширити» систему новим класом без зміни існуючого коду.

## 10. Типові помилки

**Помилка 1: забули `virtual`**
```c++
class Animal {
public:
    void makeSound() {}   // без virtual — статичний зв'язування
};
```
Результат: при виклику через `Animal*` завжди викликається `Animal::makeSound()`, навіть якщо об'єкт — `Dog`.

**Помилка 2: забули `override`**
```c++
class Dog : public Animal {
public:
    void makeSound() {}   // ✅ компілятор мовчить, але є помилка!
};
```
Помилка може просиджувати довго непоміченою. З `override` компілятор знайде її одразу.

**Помилка: різниця назв**
```c++
class Dog : public Animal {
public:
    void MakeSound() override {}   // ❌ MakeSound != makeSound (регістр!)
};
```
