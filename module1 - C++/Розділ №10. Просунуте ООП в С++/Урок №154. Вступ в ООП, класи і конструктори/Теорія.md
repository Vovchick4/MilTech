# Урок №154. Вступ в ООП, класи і конструктори

## 1. Що таке ООП?

**ООП (об'єктно-орієнтоване програмування)** — це спосіб написання програм, за якого дані та дії над ними об'єднуються в одне ціле — в **об'єкти**.

Уявіть реальний світ. Автомобіль має:
- *дані*: марку, швидкість, колір, рік;
- *дії*: їхати, гальмувати, повертати, сигналити.

ООП дозволяє перенести цю ж логіку в код: об'єкт `Car` зберігає свої дані **всередині себе** і сам реалізує дії.

## 2. Чим ООП відрізняється від процедурного програмування?

У **процедурному** підході (базовий C++) дані та функції розділені:

```c++
struct Student {
    string name;
    int age;
    int grade;
};

void printStudent(Student s) { ... }   // функція «знає» про структуру
void increaseGrade(Student& s) { ... } // бо та сама функція змінює дані
```

Проблема: вся програма — це велика кількість даних і функцій, розкиданих по коду. Важко стежити, *хто може змінити* дані та *коли*.

У **ООП** дані та методи зібрані в класі:

```c++
class Student {
private:
    string name;
    int age;
    int grade;

public:
    void print();       // метод сам «знає» свої дані
    void increaseGrade(){ }
};
```

Головна думка: **об'єкт сам контролює свої дані** і ніхто ззовні не може їх зіпсувати.

## 3. Що таке клас і об'єкт?

- **Клас** — це *шаблон* (креслення). Він описує, які дані (поля) та які дії (методи) матимуть об'єкти.
- **Об'єкт** — це *конкретний екземпляр* класу, створений за цим шаблоном.

Аналогія: **клас** — це форма для печива, а **об'єкти** — печиво, випечене за цією формою. Форма одна, а печива можна зробити багато, і кожне трохи інше.

## 4. Синтаксис класу

```c++
class Car {
public:
    string brand;
    int speed;

    void drive() {
        cout << brand << " is driving";
    }
};
```

## 5. Розбір коду

- `class Car { ... };` — оголошення класу із назвою `Car`. Наприкінці обов'язково крапка з комою.
- `public:` — специфікатор доступу. Поля й методи після нього доступні ззовні (детально — в розділі про access modifiers).
- `string brand;` і `int speed;` — **поля** (змінні-члени). Це дані об'єкта: марка і швидкість.
- `void drive()` — **метод** (функція-член). Це дія, яку вміє виконувати об'єкт. Він має доступ до полів цього ж об'єкта (`brand`).

## 6. Створення об'єкта

```c++
Car car;              // створюємо об'єкт car типу Car

car.brand = "BMW";    // записуємо поле бренд
car.speed = 100;      // записуємо поле швидкість

car.drive();          // викликаємо метод drive()
```

Розбір по рядках:
- `Car car;` — створюємо об'єкт `car` класу `Car`. Це «печиво» з форми.
- `car.brand = "BMW";` — звертаємось до поля об'єкта через крапку (`.`) і присвоюємо значення. Тепер у цього конкретного об'єкта марка «BMW».
- `car.speed = 100;` — аналогічно для швидкості.
- `car.drive();` — викликаємо метод. Він виведе `BMW is driving`, бо всередині методу змінна `brand` — це поле саме цього об'єкта `car`.

## 7. Стан і поведінка об'єкта

- **Стан** — це значення всіх полів об'єкта в даний момент (марка = BMW, швидкість = 100).
- **Поведінка** — це те, що об'єкт робить через свої методи (`drive()`, `brake()`, ...).

Можна створити два об'єкти одного класу — у них однакова *поведінка*, але різний *стан*:

```c++
Car car1;
car1.brand = "BMW";
car1.speed = 100;

Car car2;
car2.brand = "Toyota";
car2.speed = 60;
```

`car1.drive()` виведе `BMW is driving`, а `car2.drive()` — `Toyota is driving`. Один клас, два різних об'єкти.

## 8. Access Modifiers (специфікатори доступу)

Це ключові слова, які вказують, **хто може звертатися** до полів і методів класу.

| Modifier  | Сам клас | Дочірній клас | Ззовні |
| --------- | -------- | ------------- | ------ |
| public    | ✅        | ✅             | ✅      |
| protected | ✅        | ✅             | ❌      |
| private   | ✅        | ❌             | ❌      |

Що означають колонки:
- **Сам клас** — чи може клас звертатися до власних членів. Завжди ✅.
- **Дочірній клас** — чи може клас-нащадок (клас, який «успадкував» цей) звертатися до членів. Це стане зрозуміло після розділу про наслідування.
- **Ззовні** — чи можемо звертатися з `main()` або з будь-якого іншого місця.

```c++
class Account {
public:          // доступно всім
    string ownerName;

private:         // доступно тільки цьому класу
    double balance;

protected:       // доступно цьому класу і нащадкам
    int accountId;
};

int main() {
    Account a;
    a.ownerName = "Ivan";   // ✅ public
    a.balance = 100;        // ❌ private — помилка компіляції!
    a.accountId = 5;        // ❌ protected — помилка компіляції!
}
```

### Чому `private` важливіший за `protected`?

- `private` — найсуворіший. Тільки сам клас.
- `protected` — як `private`, але ще й дочірні класи.

Якщо поле `private` — дочірній клас НЕ може напряму звертатись до нього; він змушений користуватись публічними методами (геттерами). Це часто краще, бо змушує використовувати перевірені методи.

## 9. Інкапсуляція

**Інкапсуляція** — це приховування внутрішніх даних класу і контроль доступу до них через методи.

Проста ідея: дані класу — `private`, а ззовні ними керують через **публічні методи**. Клас «сам знає», як правильно поводитись зі своїми даними, і не дозволяє зіпсувати їх ззовні.

### Неправильно (усі поля відкриті):

```c++
class BankAccount {
public:
    double balance;
};

int main() {
    BankAccount my;
    my.balance = -100000;   // ❌ можна, але це безглуздо!
}
```

Проблема: ніхто не завадить записати від'ємний баланс.

### Правильно (інкапсуляція):

```c++
class BankAccount {
private:
    double balance = 0;

public:
    void deposit(double amount) {
        if (amount > 0) {
            balance += amount;
        }
    }

    void withdraw(double amount) {
        if (amount > 0 && amount <= balance) {
            balance -= amount;
        }
    }

    double getBalance() {
        return balance;
    }
};

int main() {
    BankAccount account;
    account.withdraw(100);   // ✅ клас сам перевіряє, чи можна
    account.balance = -5;    // ❌ помилка — private!
}
```

Тепер неможливо напряму записати від'ємний баланс — клас контролює власний стан через валідацію в методах.

### Розділення даних і методів

Щоб інкапсуляція була повною, ззовні зазвичай:
- **не читають** поля напряму — використовують **геттери** (`getBalance()` — метод, який повертає значення);
- **не записують** поля напряму — використовують **сеттери** (`setName()`) або спеціальні методи.

Бонус: ми можемо змінити внутрішню реалізацію класу, а код ззовні не зміниться. Це і є інкапсуляція — зовні клас виглядає як «чорна скринька» з методами.

## 10. Конструктори

**Конструктор** — спеціальний метод, який автоматично викликається **у момент створення** об'єкта. Його головна мета — задати правильний початковий стан.

Правила:
- назва конструктора збігається з назвою класу;
- у конструктора **немає типу повернення** (навіть `void`);
- конструктор викликається один раз — при створенні об'єкта.

### Навіщо він потрібен?

Без конструктора поля можуть містити «сміття» (випадкові значення), або ми змушені налаштовувати об'єкт вручну через кілька присвоєнь. Конструктор гарантує: **об'єкт створюється вже правильним**.

### Конструктор за замовчуванням

```c++
class Car {
private:
    string brand;
    int speed;

public:
    Car() {            // конструктор без параметрів
        brand = "Unknown";
        speed = 0;
    }
};

Car car;  // викликається Car() → brand="Unknown", speed=0
```

### Конструктор з параметрами

```c++
class Car {
private:
    string brand;
    int speed;

public:
    Car(string brand, int speed) {
        // проблема: параметр brand «перекриває» поле brand
    }
};
```

### `this` — вказівник на сам об'єкт

Коли параметр і поле називаються однаково (`brand` і `brand`), компілятор не знає, де поле, а де параметр. У цьому допомагає **`this`** — вказівник, який завжди вказує на поточний об'єкт.

Різниця між:

```c++
brand = brand;   // ❌ обидва — параметри! поле не змінилось
```

і:

```c++
this->brand = brand;   // ✅ this->brand — це поле, brand — параметр
```

Розбір:
- `this` — це адреса поточного об'єкта;
- `this->brand` — звернення до поля *об'єкта*;
- `brand` (без `this->`) — в цьому контексті змінна, що найближче — параметр.

### 11. Кілька конструкторів (перевантаження)

Клас може мати **кілька конструкторів** з різним набором параметрів.

```c++
class Car {
private:
    string brand;
    int speed;

public:
    Car()                       // без параметрів
        : brand("Unknown"), speed(0) {}

    Car(string brand, int speed)  // з параметрами
        : brand(brand), speed(speed) {}

    Car(string brand)             // тільки марка
        : brand(brand), speed(0) {}
};

Car c1;                       // "Unknown", 0
Car c2("BMW", 100);           // "BMW", 100
Car c3("Toyota");             // "Toyota", 0
```

## 12. Список ініціалізації (initialization list)

Замість присвоєння в тілі конструктора:

```c++
Car(string brand, int speed) {
    this->brand = brand;   // присвоєння (другий крок)
    this->speed = speed;
}
```

краще використовувати **список ініціалізації**:

```c++
Car(string brand, int speed)
    : brand(brand), speed(speed)   // ініціалізація (перший крок)
{
}
```

### В чому різниця?

- `this->brand = brand;` — це **присвоєння**: спочатку поле створюється зі стандартним значенням, а потім йому перезаписують значення.
- `: brand(brand)` — це **ініціалізація**: поле одразу створюється з потрібним значенням.

Для простих `int`/`string` різниця невелика, але для складних об'єктів вона суттєва (економія «зайвого» кроку).

### Коли список ініціалізації є ОБОВ'ЯЗКОВИМ?

Коли поля не можна «присвоїти» після створення, а лише ініціалізувати одразу. Наприклад:

1. **`const`-поля** — константі можна надати значення лише при створенні:

```c++
class Circle {
private:
    const double PI;   // const-поле

public:
    Circle(double pi)
        : PI(pi)   // ОБОВ'ЯЗКОВО через список ініціалізації
    {
        // PI = pi; // ❌ помилка — const не можна змінювати після створення
    }
};
```

2. **Поля-посилання** (`&`) — посилання не можна «перепризначити», його лише ініціалізують:

```c++
class Holder {
private:
    int& ref;   // посилання

public:
    Holder(int& value)
        : ref(value)   // ОБОВ'ЯЗКОВО ініціалізувати посилання!
    {}
};
```

3. **Поля-об'єкти інших класів**, у яких немає конструктора за замовчуванням:

```c++
class Engine {
public:
    Engine(string type) {}   // немає конструктора без параметрів
};

class Car {
private:
    Engine engine;

public:
    Car(string type)
        : engine(type)   // ОБОВ'ЯЗКОВО — інакше Car не зможе створити Engine
    {}
};
```

4. **Базовий клас при наслідуванні** (детально в уроках про наслідування):

```c++
class Dog : public Animal {
public:
    Dog(string name)
        : Animal(name)   // виклик конструктора батьківського класу
    {}
};
```

### Правило

Намагайтесь **завжди** використовувати список ініціалізації замість присвоєння в тілі. Це правильніший і читабельніший спосіб.

## 13. Коли використовувати: коротко

- **Класи** — коли дані + дії логічно належать одному поняттю (Car, Student, BankAccount).
- **private** поля + публічні методи — майже завжди (інкапсуляція).
- **Конструктор** — для коректного початкового стану.
- **Список ініціалізації** — завжди, коли можливо.

## 14. Типові помилки

**Помилка: забули крапку з комою після класу**
```c++
class Car { ... }   // ❌ немає крапки з комою
```

**Помилка: `brand = brand;` (не змінює поле)**
```c++
Car(string brand) {
    brand = brand;   // ❌ присвоєння параметру самого себе
}
```
Правильно:
```c++
Car(string brand)
    : brand(brand)   // ✅ або this->brand = brand у тілі
{}
```

**Помилка: const-поле без списку ініціалізації**
```c++
class A {
    const int x;
public:
    A(int val) { x = val; }   // ❌ помилка
};
```
Правильно:
```c++
class A {
    const int x;
public:
    A(int val) : x(val) {}   // ✅
};
```
