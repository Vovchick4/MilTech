# Урок №155. Наслідування в С++

## 1. Що таке наслідування?

**Наслідування (inheritance)** — це механізм ООП, за якого один клас **(дочірній, нащадок, derived)** отримує поля та методи іншого класу **(батьківський, базовий, base)**.

Мета — **повторне використання коду** та побудова ієрархії понять.

Аналогія: батько і дитина. Дитина «успадковує» від батька якісь риси (колір очей, зріст), але має й свої (вміє те, чого батько не вміє).

## 2. Синтаксис

```c++
class Dog : public Animal {
    // Dog успадковує все від Animal і додає своє
};
```

## 3. Що означає `:`?

Двокрапка — це знак «наслідується від». Читається: «клас `Dog` успадковує від класу `Animal`».

## 4. Що означає `public Animal`?

Тут `public` — це **тип наслідування**. Він визначає, як члени батьківського класу будуть видимі в дочірньому.

Важливо пам'ятати правило зменшення доступу:

| Член базового класу | Після `public`-наслідування | Після `protected`-наслідування | Після `private`-наслідування |
| ------------------- | --------------------------- | ------------------------------ | ----------------------------- |
| public              | public                      | protected                      | private                       |
| protected           | protected                   | protected                      | private                       |
| private             | недоступний                 | недоступний                    | недоступний                   |

Практично завжди використовується **`public`-наслідування** — воно зберігає доступність членів. Інші види рідкісні й зменшують доступ.

## 5. Що саме успадковується?

Дочірній клас автоматично отримує **усі не-`private`** члени батьківського:
- `public` поля і методи — стають доступні;
- `protected` поля і методи — стають доступні *дочірньому класу*;
- `private` члени — **успадковуються технічно**, але **недоступні** дочірньому класу напряму. До них можна звертатись лише через публічні/Protected методи батька.

## 6. Простий приклад і розбір

```c++
class Animal {
protected:
    string name;

public:
    Animal(string name)
        : name(name)
    {
    }

    void eat() {
        cout << name << " is eating";
    }
};

class Dog : public Animal {
public:
    Dog(string name)
        : Animal(name)   // викликаємо конструктор батьківського класу
    {
    }

    void bark() {
        cout << name << " says Woof";
    }
};

int main() {
    Dog dog("Rex");

    dog.eat();    // успадкований метод Animal
    dog.bark();   // власний метод Dog
    return 0;
}
```

Розбір важливих рядків:
- `protected: string name;` — поле `name` доступне і класу `Animal`, і його нащадкам (`Dog`). Тому в `Dog::bark()` ми можемо звертатись до `name` напряму.
- `Dog(string name) : Animal(name) {}` — дочірній конструктор викликає конструктор батька через список ініціалізації. Без цього не створиться частина `Animal` (детально — в наступному уроці).
- `dog.eat();` — метод `eat()` не визначений у `Dog`, але «прийшов» з `Animal`. Тому його можна викликати.
- `dog.bark();` — власний метод `Dog`, якого немає в `Animal`.

Результат:
```
Rex is eating
Rex says Woof
```

**Ключове**: `Dog` тепер вміє все, що вміє `Animal`, плюс власні дії. Це і є наслідування.

## 7. Що таке `IS-A` відношення

Наслідування описує відношення **«IS-A»** (є різновидом / є):
- Собака **є** твариною → `Dog : Animal`;
- Автомобіль **є** транспортним засобом → `Car : Vehicle`;
- Квадрат **є** прямокутником → `Square : Rectangle`.

Якщо поняття НЕ є різновидом іншого — наслідування, швидше за все, недоречне.

## 8. Типи наслідування

Існують кілька видів наслідування за структурою ієрархії.

### 8.1 Single inheritance (одинарне)

Один клас — один батько:

```
    Animal
       ↓
      Dog
```

```c++
class Animal {};
class Dog : public Animal {};
```

### 8.2 Multilevel inheritance (багаторівневе)

Ланцюжок: A → B → C.

```
    Animal
       ↓
    Mammal
       ↓
      Dog
```

```c++
class Animal {};
class Mammal : public Animal {};
class Dog : public Mammal {};
```

Тут `Dog` отримує все від `Mammal`, а `Mammal` — все від `Animal`. Тобто `Dog` має властивості і `Mammal`, і `Animal`.

### 8.3 Hierarchical inheritance (ієрархічне)

Один батько — кілька нащадків.

```
          Animal
        /        \
      Dog        Cat
```

```c++
class Animal {};
class Dog : public Animal {};
class Cat : public Animal {};
```

### 8.4 Multiple inheritance (множинне)

Клас наслідує одразу від **кількох** класів.

```
   Flyable     Swimmable
        \       /
         Duck
```

```c++
class Flyable {
public:
    void fly() {}
};

class Swimmable {
public:
    void swim() {}
};

class Duck : public Flyable, public Swimmable {
};

int main() {
    Duck d;
    d.fly();    // від Flyable
    d.swim();   // від Swimmable
    return 0;
}
```

#### Переваги multiple inheritance

- Повторне використання логіки з різних «джерел»;
- Зручно для реалізації «можливостей» (тварини, що вміють і літати, і плавати).

#### Проблеми multiple inheritance

- **Конфлікт імен (diamond problem)**: якщо два батьки мають методи з однаковими назвами, незрозуміло, який викликати.

```c++
class A { public: void go() {} };
class B { public: void go() {} };
class C : public A, public B {};

C obj;
obj.go();   // ❌ неоднозначно: A::go чи B::go?
```

Розв'язок — явна вказівка: `obj.A::go();`

- Зростає складність коду й імовірність помилок.

**Практична порада**: у навчальних проєктах і більшості реальних задач використовуйте single/multilevel/hierarchical наслідування. Multiple — лише коли без нього не обійтись (зазвичай у вигляді `interface`-подібних базових класів).

## 9. Коли використовувати наслідування

- Коли є чітке відношення **«IS-A»** (велосипед — це транспорт);
- Коли потрібно розширити поведінку класу, додавши нові поля/методи;
- Коли кілька класів мають спільну логіку — винести її в базовий клас.

## 10. Типові помилки

**Помилка: дочірній клас не викликає конструктор батька, а батьківський не має конструктора за замовчуванням**
```c++
class Animal {
public:
    Animal(string name) {}
};

class Dog : public Animal {
    // ❌ Animal не має конструктора без параметрів,
    //    тож Dog не може його неявно викликати
};
```

**Помилка: доступ до `private` поля батька напряму**
```c++
class Animal {
private:
    string name;   // private!
};

class Dog : public Animal {
public:
    void show() {
        cout << name;   // ❌ name private — недоступний нащадку
    }
};
```
Правильно: зробити поле `protected` або додати геттер.
