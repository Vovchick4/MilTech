# 2. Лінійні структури

## 2.1 Масив і `std::vector`

```
vector:  [ 10 | 20 | 30 | 40 |    |    ]   size = 4, capacity = 6
           ^ data()
```

- Елементи лежать **підряд** → `v[i]` = `*(data + i)`, O(1), ідеально для кешу.
- `push_back`: є місце → O(1); немає → виділити ×2, перемістити все, звільнити старе.
- `insert/erase` у середині — зсув хвоста, O(n).

**Інвалідація ітераторів** — класична помилка:

```cpp
std::vector<int> v{1, 2, 3};
int& first = v[0];
v.push_back(4);          // реалокація!
std::cout << first;      // UB: посилання на звільнену пам'ять (ASan це покаже)
```

## 2.2 Зв'язний список

```
head -> [10|*] -> [20|*] -> [30|null]
```

- Вставка/видалення **за відомою позицією** — O(1), без зсувів.
- Доступ до i-го — O(n), погано для кешу.
- Реальна користь: `std::list::splice` (перенести вузол за O(1)), ітератори не інвалідуються → LRU-кеш (задача T04).

Код: `include/dsa/linked_list.hpp`. Зверни увагу на:
- `reverse()` — розворот на місці, O(n) часу, O(1) пам'яті (класична співбесідна задача);
- деструктор — ітеративний, бо рекурсивний на 10⁶ вузлів переповнить стек
  (тест `LinkedList: reverse + big list destructor`).

## 2.3 Стек, черга, дек

| Структура | Принцип | Операції | STL | На дроні |
|---|---|---|---|---|
| Стек | LIFO | push / pop / top | `std::stack` | відкат команд, DFS, парсер виразів |
| Черга | FIFO | push / pop / front | `std::queue` | черга вхідних MAVLink-пакетів, BFS |
| Дек | обидва кінці | push/pop front/back | `std::deque` | монотонна черга (2.5) |

## 2.4 Кільцевий буфер (ring buffer)

Черга фіксованого розміру поверх масиву: два індекси, що «загортаються» по модулю N.

```
capacity = 5, size = 3          після ще 3 push (перезапис найстарішого)
[ . | A | B | C | . ]           [ F | . | C | D | E ]  ... і т.д.
      ^oldest   ^head
```

Чому це головна структура embedded-коду:

- пам'ять виділена один раз (`std::array`), **нуль алокацій у польоті**;
- `push` — O(1) завжди, не «амортизовано»;
- природно зберігає «останні N вимірів».

Де в ArduPilot: `ByteBuffer` / `ObjectBuffer` (UART, MAVLink), історія для EKF (затримані виміри GPS).

Код: `include/dsa/ring_buffer.hpp`. Індекс найстарішого: `(head + N - size) % N`.

> Оптимізація: якщо N — степінь двійки, `% N` замінюють на `& (N - 1)` — швидше на MCU без
> апаратного ділення.

## 2.5 Фільтри ковзного вікна

`include/dsa/filters.hpp`, приклад `./build/02_telemetry_filters`.

| Фільтр | Складність кроку | Що робить | Проблема |
|---|---|---|---|
| `MovingAverage<N>` | O(1) — біжуча сума | згладжує шум | відстає, «розмазує» стрибки |
| `MedianFilter<N>` | O(N) — `nth_element` | прибирає поодинокі викиди | для великих N — дорого |

Фрагмент запуску (висота з бароміра, справжня висота = t):

```
  t | true  | raw    | avg5   | median5
  5 |   5.0 |   44.6 |   10.6 |     2.8   <- glitch: середнє «злетіло», медіана — ні
  6 |   6.0 |    6.5 |   11.8 |     3.9
```

### Монотонна черга

Як знайти мінімум за останні N значень за O(1), а не O(N)? Тримаємо в деку тільки
«кандидатів», значення в ньому зростають:

```
нове x: поки back >= x — pop_back (вони вже ніколи не будуть мінімумом)
        push_back(x)
        якщо front вийшов за вікно — pop_front
мінімум = front
```

Кожен елемент один раз потрапляє в дек і один раз виходить → O(1) амортизовано.
Максимум за вікно — **задача T01**.

## Питання

1. Чому `int& first = v[0]; v.push_back(...)` — UB, а для `std::list` — ні?
2. Як у кільцевому буфері відрізнити «порожній» від «повного», якщо `head == tail`?
   (у нашій реалізації — окремий лічильник `size_`; інший варіант — завжди лишати одну комірку порожньою)
3. Чому медіанний фільтр не підходить для згладжування, а середнє — для прибирання викидів?
