# 4. Сортування і пошук

## 4.1 Алгоритми сортування

Код: `include/dsa/sort.hpp`, бенчмарк: `./build/06_sort_bench`.

| Алгоритм | Кращий | Середній | Гірший | Пам'ять | Стабільний | Ідея |
|---|---|---|---|---|---|---|
| Insertion | O(n) | O(n²) | O(n²) | O(1) | так | вставляємо кожен елемент на місце у відсортований префікс |
| Merge | O(n log n) | O(n log n) | O(n log n) | O(n) | так | поділити навпіл, відсортувати, злити |
| Quick | O(n log n) | O(n log n) | O(n²) | O(log n) | ні | розбити навколо pivot, рекурсія |
| Heap | O(n log n) | O(n log n) | O(n log n) | O(1) | ні | купа + витягування максимуму |
| Counting | O(n + k) | | | O(k) | так | ключі — малі цілі (0..k) |
| `std::sort` | | O(n log n) | O(n log n) | O(log n) | ні | introsort: quick → heap при глибокій рекурсії → insertion на дрібних |

Результат з нашого запуску:

```
     n | insertion |   merge   |   quick   | std::sort
  1000 |   0.11 ms |   0.04 ms |   0.04 ms |   0.04 ms
 30000 |  83.03 ms |   1.92 ms |   1.63 ms |   1.57 ms     <- n² вже в 50 разів гірше
1000000|      —    |  86.42 ms |  73.55 ms |  68.22 ms
```

**Стабільність** — рівні елементи зберігають вихідний порядок. Приклад: точки треку відсортовані
за часом; сортуємо стабільно за висотою — в межах однієї висоти порядок за часом зберігся.
Тест `Sorts: merge sort is stable`.

**Чому медіана з трьох.** Наївний quick sort з pivot = перший елемент на вже відсортованому масиві
ділить n на (0, n-1) → O(n²) і рекурсія глибиною n → переповнення стека. Наш `quick_sort`:
медіана з трьох + рекурсія тільки в меншу половину (глибина O(log n)) + insertion sort на шматках ≤ 16.

## 4.2 Бінарний пошук

У **відсортованому** масиві — O(log n): 1 000 000 елементів → 20 порівнянь.

```cpp
std::size_t lo = 0, hi = a.size();          // шукаємо в [lo, hi)
while (lo < hi) {
    std::size_t mid = lo + (hi - lo) / 2;   // не (lo + hi) / 2 — переповнення на великих індексах
    if (a[mid] < x) lo = mid + 1;
    else            hi = mid;
}
return lo;                                  // перший елемент >= x  (lower_bound)
```

Типові помилки: `<=` замість `<`, `hi = a.size() - 1` з півінтервалом, нескінченний цикл з `lo = mid`.

### Бінарний пошук «по відповіді»

Якщо функція монотонна, можна шукати не елемент, а **значення параметра**:
«яка максимальна швидкість, при якій заряду вистачить на маршрут?» — `can_fly(speed)` монотонна,
бінарний пошук по speed з точністю 0.1 м/с — ~10 викликів симуляції замість сотень.

## 4.3 Два вказівники і ковзне вікно

**Два вказівники** — у відсортованому масиві шукаємо пару з сумою S за O(n):
`l` з початку, `r` з кінця; сума мала → `l++`, велика → `r--`.

**Ковзне вікно** — властивість усіх підмасивів довжини k за O(n), а не O(n·k):
біжуча сума (`MovingAverage`), монотонна черга (`MovingMin`, задача T01).

**Об'єднання інтервалів** (задача T07): сортуємо за початком — і один прохід.

## 4.4 Робота з бітами

На дроні — всюди: прапорці стану (`MAV_MODE_FLAG_SAFETY_ARMED = 128`), регістри датчиків,
контрольні суми.

```cpp
bool armed = (base_mode & 0x80) != 0;     // перевірити біт 7
flags |=  (1u << 3);                      // встановити біт 3
flags &= ~(1u << 3);                      // скинути біт 3
uint8_t lo = static_cast<uint8_t>(crc & 0xFF), hi = static_cast<uint8_t>(crc >> 8);
```

Пастки: зсув знакового числа, зсув на ≥ ширину типу (UB), неявне розширення `uint8_t` до `int`
у виразах (`uint8_t x = ...; x << 4` — це вже `int`, а не 8 біт!). Задача **T08** — CRC MAVLink,
де саме це і треба врахувати.
