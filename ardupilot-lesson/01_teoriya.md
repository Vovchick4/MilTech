# 1. Теорія: як усе це працює

## 1.1 Компоненти

| Компонент | Що це | Аналогія |
|---|---|---|
| **ArduPilot** | Прошивка автопілота (C++). Стабілізація, навігація, режими, failsafe. Працює на польотному контролері (Pixhawk, Cube, Matek…) | «Мозок» дрона |
| **SITL** (Software In The Loop) | Та сама прошивка ArduPilot, зібрана для ПК + фізичний симулятор (мотори, GPS, IMU, батарея) | Дрон усередині комп'ютера |
| **MAVLink** | Бінарний протокол повідомлень між дроном і всім іншим (HEARTBEAT, GLOBAL_POSITION_INT, COMMAND_LONG…) | «Мова», якою говорить дрон |
| **GCS** — Mission Planner / QGroundControl | Наземна станція: карта, телеметрія, параметри, місії, кнопки ARM/Takeoff | Пульт оператора |
| **MAVSDK** | C++ бібліотека, яка ховає «сирий» MAVLink за зручним API (`action.arm()`, `telemetry.position()`) | Драйвер/SDK для нашої програми |
| **Наша C++ програма** | Логіка місії: куди летіти, коли садитись | Автономний «оператор» |

> Важливо: код ArduPilot у SITL **той самий**, що на реальному дроні.
> Якщо C++ програма працює з SITL — вона так само працюватиме з реальним
> польотним контролером, змінюється лише рядок підключення
> (`tcp://...` → `serial:///dev/ttyUSB0:57600` або `udp://...` з телеметрійного модема).

## 1.2 Схема підключень у нашому уроці

```
                ┌───────────────────────────────┐
                │      ArduPilot SITL           │
                │  (arducopter --model quad)    │
                │                               │
                │  SERIAL0 ── TCP 5760 ─────────┼──► Mission Planner / QGC
                │  SERIAL1 ── TCP 5762 ─────────┼──► C++ програма (MAVSDK)
                │  SERIAL2 ── TCP 5763 ─────────┼──► вільний (MAVProxy, 2-й скрипт)
                └───────────────────────────────┘
```

**Кожен TCP-порт SITL приймає тільки ОДНОГО клієнта.**
Тому Mission Planner сидить на 5760, а C++ — на 5762. Обидва бачать один і той самий дрон
одночасно: C++ командує, Mission Planner показує.

### `tcp://` vs `tcpin://` — частa помилка

| URL у MAVSDK | Хто «сервер» | Коли використовувати |
|---|---|---|
| `tcp://127.0.0.1:5762` (`tcpout`) | SITL слухає, MAVSDK **підключається** | ✅ Наш випадок |
| `tcpin://0.0.0.0:5762` | MAVSDK **слухає**, хтось підключається до нього | Коли дрон/роутер сам ініціює з'єднання |
| `udp://:14540` / `udpin://0.0.0.0:14550` | MAVSDK слухає UDP | PX4 SITL, MAVProxy `--out`, телеметрійні модеми |

`tcpin://127.0.0.1:5760` намагається **відкрити** порт 5760, який уже відкрив SITL →
`Bind error: Address already in use`.

## 1.3 `arducopter` напряму vs `sim_vehicle.py`

| Спосіб | Що відбувається | Порти |
|---|---|---|
| `build/sitl/bin/arducopter --model quad ...` (наш спосіб) | Тільки симулятор. Чекає клієнта на 5760 | TCP 5760/5762/5763 |
| `Tools/autotest/sim_vehicle.py -v ArduCopter` | Збирає, запускає SITL **+ MAVProxy**. MAVProxy сам займає 5760 і роздає UDP | UDP 14550 (GCS), 14551 |

`sim_vehicle.py` зручний, але додає MAVProxy і Python-залежності. У нашому уроці ми запускаємо
бінарник напряму — менше рухомих частин, зрозуміліше, що відбувається.

> Якщо використовуєте `sim_vehicle.py`, підключайте C++ так:
> `sim_vehicle.py -v ArduCopter --out=udp:127.0.0.1:14540` і в C++ `udpin://0.0.0.0:14540`.

## 1.4 Режими польоту ArduCopter, які нам потрібні

| Режим | Навіщо |
|---|---|
| **STABILIZE** | Ручний, дефолтний після старту |
| **GUIDED** | Керування «ззовні»: GCS або наша програма каже «лети в точку X». MAVSDK переводить сюди автоматично |
| **AUTO** | Виконання завантаженої місії (список waypoints) |
| **LAND** | Посадка на місці |
| **RTL** | Повернення додому і посадка |

> MAVSDK показує GUIDED як `Offboard` — це нормально, це просто назва в API MAVSDK.

## 1.5 Що робить MAVSDK під капотом

| Виклик C++ | MAVLink повідомлення |
|---|---|
| `first_autopilot()` | Чекає `HEARTBEAT` від компонента-автопілота |
| `telemetry.position()` | Останній `GLOBAL_POSITION_INT` |
| `action.arm()` | `COMMAND_LONG` `MAV_CMD_COMPONENT_ARM_DISARM` |
| `action.takeoff()` | режим GUIDED + `MAV_CMD_NAV_TAKEOFF` |
| `action.goto_location()` | режим GUIDED + `MAV_CMD_DO_REPOSITION` |
| `action.set_current_speed()` | `MAV_CMD_DO_CHANGE_SPEED` |
| `action.land()` / `return_to_launch()` | режим LAND / RTL |

Подивитися сирі MAVLink повідомлення: Mission Planner → `Ctrl+F` → **MAVLink Inspector**,
або QGC → Analyze Tools → MAVLink Inspector.

## 1.6 Чому чекаємо досягнення точки, а не `sleep(60s)`

`goto_location()` повертає `Success`, щойно автопілот **прийняв** команду — а не коли дрон
долетів. На 100 км політ триває годину+, і будь-який фіксований `sleep` або закороткий,
або марно довгий. Правильно — **читати телеметрію в циклі** і рахувати відстань до цілі
(формула гаверсинуса), з таймаутом і перевіркою, що дрон ще ARMED.

## 1.7 Координати: як з кілометрів отримати lat/lon

1° широти ≈ 111 320 м скрізь. 1° довготи ≈ 111 320 · cos(широта) м — стискається до полюсів.
У коді використовується точніша сферична формула:

```
Δlat = north_m / R · 180/π
Δlon = east_m  / (R · cos(lat)) · 180/π        R = 6 371 000 м
```
